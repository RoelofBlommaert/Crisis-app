Data sources, ranked by relevance + ease of actually getting working in a 2-day sprint:

1. GDELT (instability/tension signal) — easiest, most relevant, do this first
Free, no API key. UPDATE (2026-09-14): the DOC 2.0 query API (`mode=timelinevol`/`timelinetone`, the `gdeltdoc` wrapper) looked ideal for a ready-made 3-month daily "tension score" per country, but it is built for occasional interactive lookups and blocked our IP after a handful of scripted requests. We switched to GDELT's raw GKG bulk export files instead (`data.gdeltproject.org/gdeltv2/`, new file every 15 min, no key, not rate-limited). That means we no longer get a pre-built 3-month timeline for free — each run only captures a short recent snapshot, and daily/history trend data has to be accumulated ourselves by running the pull on a schedule and appending. See `Scripts/README.md` ("Avoiding the GDELT rate limit") for the full pattern, including the BigQuery option for bulk historical backfill instead of going-forward polling.

2. Eurostat / CBS travel statistics (Dutch outbound travel, seasonal baseline)
Public, stable, downloadable as CSV/JSON. Gives you "expected" vacation volume per destination per month. No API weirdness, very low risk. Good second layer.
UPDATE (2026-09-14): CBS table 84365NED only breaks out ~15 individually-named "most visited" destinations (mostly Western Europe, plus US/Turkey) — everything else is only reported at continent/region level (e.g. all of "Africa" lumped together). Of our 8 tracked crisis countries, only Turkey gets country-level numbers; the other 7 only get a region-level baseline. Treat those as rough context, not a per-country baseline — worth revisiting (e.g. Eurostat's own tourism-trips-by-destination-country dataset) if per-country travel data turns out to matter more than expected.

3. ReliefWeb / GDACS (official crisis alerts)
Both have straightforward public REST APIs returning structured JSON (disaster type, country, severity, date). Easy to layer on top of GDELT as a "confirmed crisis" marker vs. GDELT's noisier media signal.
UPDATE (2026-09-14): two gaps found once we actually wired these up. (a) ReliefWeb now requires a pre-approved `appname` (changed 1 Nov 2025, after this doc was first written) — registration is a review process, not instant, so the ReliefWeb pull is currently skipped pending approval. (b) GDACS only covers natural disasters (earthquakes, floods, storms, droughts, volcanic activity) — it has no conflict/political-crisis coverage at all, which matters a lot for this project's list since Ukraine, Lebanon, Israel, and Sudan are conflict-driven, not disaster-driven. Until ReliefWeb is approved, those 4 countries have no "confirmed event" layer, only GDELT's noisier media signal.

4. OpenSky Network (flight patterns) — this is the one to reconsider
Here's the catch I want to flag clearly: OpenSky's free/anonymous tier only gives you a live snapshot of current aircraft positions, not historical trends. Anonymous users can only get the most recent state vectors — the time parameter is ignored. Even with a registered account, you can only retrieve data up to 1 hour in the past. To get "flight volume out of country X over the past month" — which is what your idea actually needs — you'd need their historical research database (Trino/Impala), which requires a research account and is not a 2-day-course-friendly setup.

So for the "flight patterns / vacation trends" piece, I'd swap the data source, not the concept:

Use Eurostat/CBS seasonal travel statistics for the "trend" layer instead of live flight tracking — same story ("travel volume vs. what's normal for this season"), far easier data.
If you still want a live map/visual wow-factor, pull one OpenSky live snapshot for a "right now" view (that part works fine anonymously) — just don't build your core insight on it.
