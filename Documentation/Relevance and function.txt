CRISIS & CONNECTIVITY MONITOR
Documentation: Relevance & App Workings
Prepared for: 2-day vibe-coding course
Ministry of Foreign Affairs

================================================================
1. RELEVANCE
================================================================

Purpose of this document
-------------------------
This document explains why this demo app was built the way it was,
and how it works technically. It is meant as documentation for
myself and for colleagues who may want to understand, reuse, or
extend the concept after the course.

Why this topic
--------------
The app started as a learning exercise for a vibe-coding course, using
a scenario relevant to MFA work: monitoring instability abroad. A
separate strategy document (`STRATEGY.md`, kept alongside this project
but outside the repo) later gave this a sharper, specific purpose that
this app is now aligned to:

**Primary framing (per STRATEGY.md):** a proof of concept for a
*crisis coordinator*, who currently has to build up a picture of an
unfolding situation from fragmented, role-specific, human-driven
sources (policy officer, spokesperson, post) and is structurally too
slow and too error-prone as a result. The strategy's approach is
incremental automation: connect existing open sources (GDACS, GDELT)
into one coherent per-area picture first, and only later work toward
actually automating classification -- this PoC's job is to show what
data exists and how it *could* combine into a risk indication, not to
deliver a finished automatic classifier.

The MFA/coordinator needs to reason about:
- What's actually happening in an area right now (conflict? disaster?
  both? neither?), not a compressed, months-stale summary
- Whether official information is keeping pace with events on the
  ground
- Roughly how many Dutch travelers are even present, for context
- Incoming signal volume (e.g. consular calls) as a corroborating
  indicator -- not yet available for real, so a synthetic placeholder
  is used to show what combining it would look like (see below)

A tool that visualizes these signals side by side, explains what's
driving them, and is honest about their limits can support earlier
situational awareness than the current fragmented, manual process.
This remains a simplified, non-operational prototype -- not a
production tool, and per STRATEGY.md, not yet an automatic classifier
either.

Why NO internal MFA data was used
----------------------------------
The original idea involved things like tracking Dutch citizens abroad
or predicting individual travel/evacuation patterns. This was
deliberately dropped because:

- Internal MFA data (consular registrations, citizen records, case
  data) is sensitive/classified and must never be used in an
  external tool, sandbox, or vibe-coding environment.
- Even anonymized or aggregated internal data carries re-identification
  and classification risks that aren't appropriate for a course
  setting or any tool outside official, secured MFA systems.
- The learning goal (build something functional in 2 days) does not
  require real personal or internal data — public, open datasets
  give the same technical experience without any of the risk.

Everything in this app uses only public, open data sources. No
personal data, no internal MFA systems, and no classified information
are involved at any point.

================================================================
2. APP WORKINGS
================================================================

Concept
-------
The app shows, per tracked country:
1. A conflict signal and a disaster signal (0-100, illustrative, scored
   per day) derived from open news data, each paired with a real
   breakdown of *which* themes are driving it that week -- not just
   the compressed number
2. Confirmed crisis/disaster events from GDACS, split into "active
   this week" vs. "historical" by the event's own date range
3. Rough context on how many Dutch travelers visit the country (CBS),
   shown as a single context figure, not a trend-vs-crisis narrative
4. An illustrative, clearly-labelled SYNTHETIC incoming-communication-
   volume layer, showing what combining that kind of signal with the
   others could look like

The idea is to show, side by side and with real per-source freshness,
what data already exists and how it could combine into one coherent
per-area picture -- the "data-integratie" and "classificatie"
groundwork tracks from STRATEGY.md -- without touching any real
traveler, citizen, or consular data, and without pretending to be a
finished automatic classifier or a crisis forecast.

Data sources used
------------------
1. GDELT (Global Database of Events, Language, and Tone)
   - Public, free, no API key required
   - Provides article volume and average "tone" (sentiment) of global
     news coverage, filterable by keyword, country, and date range
   - Used as the core "tension score" per country over time
   - Note: the DOC 2.0 query API (originally planned) is only meant for
     occasional interactive lookups and blocks scripted/cloud IPs after
     a handful of requests. We pull from GDELT's raw GKG bulk export
     files instead (updated every 15 min, no key, not rate-limited).
     Practical effect: there is no ready-made 3-month timeline anymore —
     each run captures a short recent snapshot, and a real trend has to
     be built by running the pull on a schedule and appending over time.

2. ReliefWeb / GDACS (disaster and crisis alert databases)
   - Public REST APIs, structured JSON output
   - Provide confirmed, officially-reported crisis/disaster events
     (type, country, severity, date)
   - Used as a "confirmed event" layer on top of GDELT's noisier
     media-based signal
   - Note: ReliefWeb now requires a pre-approved `appname` (changed
     1 Nov 2025) and is currently pending, so only GDACS is live. GDACS
     covers natural disasters only (earthquakes, floods, storms,
     droughts, volcanic activity) — it has no conflict/political-crisis
     coverage, so conflict-driven countries on our list (Ukraine,
     Lebanon, Israel, Sudan) currently have no confirmed-event layer at
     all, only GDELT's media signal.

3. Eurostat / CBS (Statistics Netherlands) tourism statistics
   - Public, downloadable datasets (CSV/JSON)
   - Provide seasonal baselines for Dutch outbound travel by
     destination
   - Used as the "expected" travel volume layer, to compare against
     current signals
   - Note: CBS only breaks out ~15 individually-named "most visited"
     destinations; every other country (7 of our 8 tracked countries)
     is only available at continent/region level. Those rows are rough
     regional context, not a per-country baseline.

4. OpenSky Network (optional, live-only)
   - Public API, free anonymous access
   - IMPORTANT LIMITATION: anonymous access only returns a live
     snapshot of current aircraft positions — no historical trend
     data. Historical flight-volume analysis would require a
     registered research account and their historical database,
     which is out of scope for a 2-day build.
   - Used only for an optional "right now" live map layer, not as
     part of the core trend/insight logic

5. Incoming communication volume -- SYNTHETIC / FICTIONAL, not a real source
   - STRATEGY.md names combining the tension signal with incoming
     communication volume (e.g. consular calls) as core to the primary
     user's actual workflow, and explicitly allows synthetic/fictional
     data for sources without confirmed real access (calls, RNI,
     CBS-flights).
   - `Scripts/generate_synthetic_comms.py` produces a deterministic
     (seeded, not random-per-run), loosely-real-data-scaled fictional
     daily count per country, purely to demonstrate what this layer
     would look like combined with the others. Labelled as synthetic
     everywhere it appears in the app and docs -- never to be mistaken
     for real data, and never to be treated as validated in any way.

How the pieces fit together
----------------------------
Step 1 — Data collection
  Pull GDELT tone/volume data, ReliefWeb/GDACS event data, and
  Eurostat/CBS travel baselines for a small set of selected
  countries, over a shared date range. Because GDELT is now pulled
  as 15-minute snapshots rather than a ready-made timeline, this step
  needs to run repeatedly (e.g. a scheduled job) with results appended
  over time to build up an actual trend, rather than as a single
  one-off pull.

Step 2 — Merge
  Combine GDELT, GDACS, CBS, and the synthetic comms-volume layer into
  one dataset per country (`Scripts/merge_data.py`), scored per day so
  each day has: conflict/disaster signal, which events were actually
  active that specific day (not just "matched at some point"), the
  real theme breakdown behind the signal, and the (clearly-labelled
  real vs. synthetic) context layers.

Step 3 — Visualization
  Display results on a country-level map/dashboard:
  - Color-coded instability level (from GDELT + confirmed events)
  - A trend chart per country: tension score vs. travel volume vs.
    seasonal baseline
  - Optional: current Dutch travel advisory level shown alongside,
    to visually flag if advisory and data appear to diverge
  - Two illustrative 0-100 signal gauges per country: "conflict signal"
    and "disaster signal" (see below) -- explicitly NOT a statistical
    probability of war or disaster; there is no calibrated base rate or
    validated model behind them.

Conflict/disaster signal scoring
---------------------------------
An earlier version color-coded countries by their flat 7-day-average
GDELT tone against fixed thresholds. This stayed "Green" for Israel and
Lebanon even during heavy, clearly negative coverage, because a
week-long average dilutes acute events with routine reporting (Lebanon's
week-average tone was only -2.9, nowhere near the -4 threshold used).

Fixed by also tagging each article's GDELT GKG theme codes (verified
against a live GKG file, not assumed from documentation) as
conflict-related (ARMEDCONFLICT, PROTEST, TERROR, UNREST_BELLIGERENT,
several World Bank political-violence/war/terrorism codes) or
disaster-related (the NATURAL_DISASTER_* theme family), and scoring
**one calendar day at a time** (not one flat weekly number):
  - conflict_signal: that day's conflict-theme article share +
    that day's tone severity + a volume-spike bonus vs. the week's own
    average
  - disaster_signal: the alert level of any GDACS event whose own
    fromdate/todate range actually covers that day (weighted highest) +
    that day's disaster-theme article share
Whichever is higher drives that day's Green/Orange/Red level, and the
app labels which one ("conflict-driven" / "disaster-driven"). A 7-8 day
history strip under each gauge shows every day's score, and the "current"
badge is simply the most recent day's entry.

Scoring day-by-day (rather than "is there any matching event at all") is
itself a fix for a second bug: GDACS keeps recently-modified events
listed for a while after they're actually over, so a months-old cyclone
or earthquake would otherwise keep inflating "today's" disaster_signal
indefinitely. Those older events still appear in the country's event
list, just labelled historical instead of active.

Known nuance: GDELT tags an article with every country it *mentions*,
so a bordering or mediating country (e.g. Egypt or Turkey appearing in
Gaza-related diplomacy coverage) can pick up a real conflict-theme share
without being a combatant itself. This is a genuine property of the
underlying data, not something fixable without deeper text analysis --
documented rather than hidden.

Step 4 — Insight
  Surface which countries currently carry an elevated conflict or
  disaster signal, why (the real theme breakdown, not just the
  number), and whether that's corroborated by a confirmed GDACS event
  active this specific week -- the "what's actually happening, and
  what's driving it" pattern that gives this PoC its practical framing,
  per STRATEGY.md's classification-support purpose.

Known limitations of this prototype
-------------------------------------
- This is a demo/learning tool, not a validated analytical model.
  Correlations shown (e.g. tension vs. travel volume) are
  illustrative, not statistically verified.
- GDELT's tone/volume metrics are a proxy for media attention, not a
  direct measure of ground-truth instability.
- No personal, internal, or classified MFA data is used or should
  ever be added to this app in its current form.
- Not intended for operational decision-making; built purely to
  demonstrate technical feasibility within a 2-day course format.
- Confirmed-event coverage is currently disaster-only (GDACS); the
  4 conflict-driven countries on our list have no confirmed-event
  layer until a ReliefWeb appname is approved.
- Travel-baseline data is region-level (not per-country) for 7 of
  our 8 tracked countries, due to CBS's limited country breakdown.
- GDELT trend depth is only as long as the accumulated history of
  scheduled pulls since this pipeline started — not a true 3-month
  lookback.
- The published app is a one-time static snapshot (data pulled once,
  merged into a static file, deployed to GitHub Pages), not a
  live-refreshing dashboard. "Current" data is only as current as the
  day the snapshot was generated -- see the timestamp and the "Data
  sources & freshness" list shown in the app itself (About panel).
  Re-run the data pipeline and republish to refresh it. STRATEGY.md
  names "near-real-time engineering" as its own track; this PoC
  deliberately stays a static snapshot but makes freshness honest and
  visible rather than implying liveness it doesn't have.
- STRATEGY.md's "Flexibiliteit / hybride sturing" track (automatic
  detection running *alongside* a manual override the coordinator can
  use to confirm or correct a suggestion) has **no representation in
  this app** -- a deliberately deferred gap for a later round, not an
  oversight. The gauges remain fully automatic with no override control.
- Per STRATEGY.md, automatic crisis classification isn't required to
  work yet at this PoC stage ("classificatie hoeft nog niet automatisch
  te werken -- puur laten zien wat er aan data is"). The conflict/
  disaster gauges were kept (a deliberate choice this round) but are
  now paired with an explicit "What's happening this week" breakdown
  (real GDELT theme counts, each shown with its share of that week's
  total articles) so the app explains what's driving a score instead of
  only showing the compressed number.
- The gauge thresholds were recalibrated after an earlier version put
  almost every tracked country at Orange-or-above almost every day --
  root-caused to GDELT's broad "mentions" tagging (a bordering/mediating
  country picks up conflict-theme share without being a combatant) and
  to un-dampened noise on low-volume country-days. See
  `Scripts/merge_data.py`'s "Scoring" docstring for the exact formula
  and recalibration history.
